# Silent UI — витрина дизайн-системы

`@ivlev-dev/silent-ui` — токены, темы, layout-примитивы и компоненты Silent
Framework. Эта витрина — рабочее место для проверки компонентов в браузере:
каждая story монтируется тем же рантаймом, что и в приложении
(`@ivlev-dev/silent-core`), поэтому поведение эффектов, ref-колбэков и
`dispose()` здесь такое же, как в проде.

- Справочник по экспортам: [`docs/api/ui.md`](../../docs/api/ui.md)
- Руководство: [`docs/guides/ui.md`](../../docs/guides/ui.md)
- Пакет: `packages/ui`, stories: `packages/ui-storybook/src`

Каждый компонент-эталон (`Button`, `TextField`, `Alert`, `Dialog`, `Table`)
имеет тег `autodocs`: рядом со stories появляется страница **Docs** с
описанием компонента, primary story, args table и исходником. Остальные
компоненты подключаются к той же схеме по мере готовности.

## Темы

Тема задаётся атрибутом `data-theme="light|dark|auto"` и наследуется поддеревом.
В тулбаре переключатель **Тема** меняет `data-theme` у canvas-обёртки, а
`Palette`/`Theme` stories показывают обе темы рядом.

- `light` — светлая, значения по умолчанию;
- `dark` — тёмная;
- `auto` — системная (`prefers-color-scheme`).

Для SSR без вспышки светлой темы используйте `ThemeScript` из
`@ivlev-dev/silent-ui`.

## Как пользоваться controls

1. Откройте story с панелью **Controls** снизу.
2. Панель раскрыта по умолчанию (`parameters.controls.expanded`), значимые
   props сгруппированы, обязательные — выше (`sort: "requiredFirst"`).
3. `select`/`inline-radio` — варианты и размеры, `boolean` — состояния,
   `range` — числовые шкалы, `color` — цвета (`matchers` распознаёт
   `background`/`color`/`Date`).
4. Изменение args перерисовывает story через `renderToCanvas`; handle
   предыдущей story освобождается, утечек подписок нет.
5. Действия (`onClick`, `onClose`, `onOpenChange`) подключены через `fn()` и
   видны на вкладке **Actions**.

Тег `autodocs` добавляет страницу **Docs** с таблицей props. Для HTML-renderer'а
Storybook не выводит props из JSDoc, поэтому таблица строится из явных
`argTypes`: описание, тип, значение по умолчанию и control задаются в meta.

## Проверки витрины

```bash
pnpm --filter @ivlev-dev/silent-ui-storybook test       # unit-тесты stories
pnpm --filter @ivlev-dev/silent-ui-storybook typecheck  # tsc
pnpm --filter @ivlev-dev/silent-ui-storybook build      # static build
pnpm --filter @ivlev-dev/silent-ui-storybook check:ui   # браузер + a11y + скриншоты
```

`check:ui` проходит по всем записям `index.json`, проверяет горизонтальный
overflow, вылезающий текст, видимость элементов, `sb-errordisplay` и
критические нарушения axe-core на шести viewport'ах с DPR 1 и 2. Отчёты и
скриншоты складываются в `/tmp`. Если браузер недоступен, скрипт печатает
причину и переходит к статическим проверкам (`--strict-browser` запрещает
такой fallback — так шаг CI не пропустит сломанный браузер).
