# План производительности

Текущее состояние (`0.6.2`): `renderToString` 71 000–78 000 ops/s (0.60× от Solid 119 000–130 000) на скомпилированном приложении с `For`, гидрация 715 ops/s в jsdom (0.57x) и 15 300–22 100 ops/s в Chromium (p50 0.035–0.060 мс; на свободной машине ~0.76×, разброс из-за фоновой нагрузки), warm `pnpm build` 0.46–0.54 с, Vite build приложения Silent 60/29 мс против Solid 132/41 мс, стартовый JS **25.6 KB / 8.6 KB gzip** с `view: false` и 29.5 KB / 10.1 KB gzip в default-режиме с lazy view-чанком (+8.98 KB для VM) против 12.6 KB у Solid. Бенчмарки ограничены четырьмя CPU через `scripts/bench-cpus.mjs` и, начиная с M8, измеряют код после компилятора, а не ручные вызовы `templateHoles`/`insert`.

История шагов: 8 746 ops/s (0.32x) → дескриптор 9 772 → текстовые дыры 10 209 → гибридная адопция 11 820–12 104 → owner/реактивность 13 762–15 151 → scoped-эффект и plan-first 14 228 → fast path регионов 16 269–16 863 → массивы зависимостей 17 590 → пропуск статических выражений 18 293 → адопция списка без эффекта 18 490 → ленивые узлы элементов списка 22 531 → пул пробных проходов 23 456. Наклон `ROWS=1`→`ROWS=20`: теперь 1.1–1.5 µs/строка у Silent против 1.4 у Solid (построчная часть сравнялась), но фиксированная часть ~18–21 µs против ~11 µs — весь остающийся разрыв там.
